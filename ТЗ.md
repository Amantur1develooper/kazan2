## 🔴 Проблемы текущей архитектуры привязки ПФ

### Проблема 1 — Один материал в нескольких этапах и подпунктах
Текущая привязка: `expense_name` (строка) → `EstimateItem`.  
Но материал «Цемент» может идти и в этап 3 (фундамент), и в этап 7 (инженерные), и в несколько подпунктов одновременно.  
При текущей схеме `unique_together(estimate_item, expense_name)` один расход можно привязать только к одной позиции сметы.

### Проблема 2 — Импорт ПФ Excel нераспределён
Сейчас FloorExpense создаются при импорте 1С-файла (перемещение запасов) по этажам.  
Нет способа понять — к какому этапу/позиции сметы относится каждая строка в момент импорта.

## 📋 Что предстоит сделать

### Задача 1 — Переработка привязки ПФ (ПРИОРИТЕТ)

**Новая модель связи:**
```
FloorExpenseLink:
  floor_expense → FloorExpense (FK)
  estimate_item → EstimateItem (FK)
  ratio → Decimal (0..1, доля суммы — если один расход делится на несколько позиций)
```
Вместо привязки «имя расхода → позиция» — прямая привязка конкретной записи расхода к позиции сметы.  
Один FloorExpense может быть привязан к нескольким позициям с коэффициентами (ratio).

**Расчёт «Расходы ПФ» по позиции сметы:**
```
SUM(floor_expense.total_amount * link.ratio)
  WHERE link.estimate_item = item
    AND floor_expense.floor.stage.block = estimate.block
```

### Задача 2 — Импорт ПФ Excel с модальным окном привязки

**Текущий импорт 1С** работает по этажам (floor_parser.py).  
Нужен новый flow для Excel-файла план-факта:

**Flow:**
1. Пользователь загружает Excel план-факта (не 1С, а сводный по блоку)
2. Парсим: код, наименование, ед., кол-во, цена, сумма, этаж/этап
3. Для каждой строки ищем совпадение с позицией сметы (по имени/коду)
4. Строки без совпадения — попадают в список «нераспознанных»
5. **Модальное окно** показывает нераспознанные строки одну за одной (или списком):
   - Наименование расхода, сумма
   - Выпадающий список: выбрать позицию сметы (сгруппировано по этапу)
   - Кнопки: «Привязать», «Пропустить», «Привязать ко всем похожим»
6. После подтверждения — создаются FloorExpense + FloorExpenseLink

**Ключевые сценарии:**
- Материал уже известен (есть алиас/совпадение) → привязывается автоматически
- Материал новый → модальное окно с выбором
- Материал в нескольких позициях → пользователь задаёт % разбивки (ratio)
